Crucial Invariant: **CI success does NOT imply Lab verification.** Code syntax correctness does not guarantee runtime behavioral integrity.

### 3.2 Review Findings & Epistemic Distinctions
Every finding generated by `AICodeReviewService` is classified across 8 categories and 3 epistemic states:
- **Categories**: `BUG`, `SECURITY`, `CORRECTNESS`, `PERFORMANCE`, `MAINTAINABILITY`, `TESTING`, `API_CONTRACT`, `REGRESSION_RISK`.
- **Epistemic States**:
  - `OBSERVED`: Literal syntax constructs visible directly in the diff (e.g., hardcoded passwords, unsafe regex, raw SQL).
  - `INFERRED`: Logical deductions regarding concurrency, memory hazards, or state synchronization.
  - `HYPOTHESIS`: Suspected secondary effects requiring dynamic verification (e.g., potential latency regressions under load).

Static code review is static analysis; it is **never** runtime failure diagnosis.

### 3.3 CI Integration Model
```python
class CIRun(BaseModel):
    id: str
    commit_sha: str
    workflow: str

    started_at: str
    completed_at: Optional[str]
    duration_ms: int
    tests_total: int
    tests_passed: int
    tests_failed: int
    output_summary: Optional[str]
    artifacts: list[str]
```
`CIService` supports local execution of:
- `pytest` / unit test suites
- `npm test`
- `npm run build`
- Deterministic simulated suites (`simulated_pass`, `simulated_fail`)

CI gates are 100% deterministic. An LLM cannot override a failed CI check.

## 4. Release Readiness Gate Matrix

`ReleaseReadinessService` evaluates four distinct gates before recommending human sign-off:

| Gate | Requirements | Epistemic Rule |
| :--- | :--- | :--- |
| **Review Gate** | AI Code Review `APPROVED` with 0 critical/high findings. | Unaddressed comments remain `PENDING`. |
| **CI Gate** | Deterministic unit tests and builds have `PASSED` on target commit SHA. | `FAILED` CI check blocks release immediately. |
| **Lab Gate** | Runtime verification session completed on target application with 0 unmitigated failures. | `ABSTAINED` or `UNKNOWN` preserves inconclusive state; never becomes `PASSED`. |
| **Evidence Gate** | Cryptographic evidence artifacts recorded and hashed with SHA-256. | Missing run logs or broken artifact chain blocks release. |

Possible Overall States:
- `NOT_READY`: Gates are still pending or missing.
- `BLOCKED`: One or more gates actively failed.
- `READY_FOR_HUMAN_REVIEW`: Gates passed; awaiting human inspection.
- `READY_FOR_RELEASE`: All automated gates verified. **Does not trigger automatic deployment.**

## 5. Antigravity Skill Workflow Integration

Antigravity agents invoke tools through `.agents/skills/engineering-lab/SKILL.md` following the Definition of Done:

```text
IMPLEMENTED
  → LOCAL_TESTED
    → COMMITTED
      → PR_CREATED
        → REVIEWED
          → CI_VERIFIED
            → LAB_VERIFIED
              → EVIDENCE_RECORDED
                → READY_FOR_HUMAN_RELEASE
```
Agents record structured engineering facts, actions, and evidence hashes in `references/engineering-trace.md` without exposing hidden chain-of-thought tokens.
